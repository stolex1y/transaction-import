ЗАДАЧА D04 — ВЛИЯНИЕ TEMPERATURE НА СТАБИЛЬНОСТЬ ОТВЕТА

Ниже приведён один и тот же синтетический журнал операций. Задание будет
запускаться многократно с одинаковым текстом; между запусками изменяется только
параметр temperature. Решение должно быть детерминированным по правилам ниже.
Не используй внешние знания, не меняй правила и не добавляй операции, которых
нет во входе.

ПРАВИЛА РАЗБОРА

1. Обработай все строки с идентификаторами ROW-01 ... ROW-10.
2. Сумма должна быть неотрицательным целым числом в минимальных единицах RUB.
   Знак исходной суммы определяет направление: минус — expense, плюс — income.
3. Категорию выбирай только из этого каталога:
   `food.groceries`, `food.cafe`, `services.digital`, `transfer.internal`,
   `health.pharmacy`, `transport`, `income.salary`.
4. Если merchant или контекст не позволяют надёжно выбрать категорию, верни
   `category_id=null` и `needs_review=true`; не угадывай.
5. Возврат является income и включается в net, но при отсутствии категории
   требует ручной проверки.
6. Перевод между своими счетами классифицируй как internal_transfer и не
   включай в net income/expense.
7. ROW-07 — точный дубликат ROW-03 по дате, merchant и сумме. Это повторная
   строка выгрузки, а не новая операция: укажи `kind="duplicate"` и не включай
   её в итоговые суммы.
8. ROW-10 — справочная строка о лимите, а не операция: укажи `kind="noise"` и
   не включай её в итоговые суммы.
9. Сохрани порядок строк и обработай каждую строку ровно один раз.

ФОРМАТ ОТВЕТА

Верни ровно один JSON-объект без Markdown fence, пояснений до или после JSON
и неизвестных полей:

{
  "rows": [
    {
      "id": "ROW-01",
      "kind": "expense",
      "amount_minor": 125000,
      "currency": "RUB",
      "category_id": "food.groceries",
      "include_in_net": true,
      "is_duplicate": false,
      "needs_review": false,
      "reason": null
    }
  ],
  "summary": {
    "expense_minor": 0,
    "income_minor": 0,
    "net_minor": 0,
    "duplicate_ids": [],
    "noise_ids": [],
    "review_ids": []
  }
}

Допустимые значения `kind`: `expense`, `income`, `internal_transfer`,
`duplicate`, `noise`. Для каждой строки обязательны поля `id`, `kind`,
`amount_minor`, `currency`, `category_id`, `include_in_net`, `is_duplicate`,
`needs_review` и `reason`. Для `duplicate` и `noise` используй
`include_in_net=false`. Для `internal_transfer` также используй
`include_in_net=false`. Для строк с неопределённой категорией используй
`category_id=null` и добавь причину в `reason`.

В `summary` посчитай только уникальные expense/income операции с
`include_in_net=true`. `net_minor` равен `income_minor - expense_minor`.
Заверши ответ сразу после закрывающей скобки корневого JSON-объекта.
