# Руководство по интерфейсу Transaction Import

Transaction Import — локальное web-приложение для подготовки структурированных операций из текста банковской выписки. Оно не записывает данные в финансовый ledger. Для внешнего LLM provider используйте только синтетические или обезличенные данные.

## Панели приложения

Основной интерфейс доступен по адресу `http://127.0.0.1:8080/agent` после запуска приложения. Верхняя навигация содержит панели «Сессии», «Фоновые задачи», «MCP» и «Настройки»; support assistant доступен в отдельной вкладке «Поддержка».

## Создание импорта

1. Откройте «Сессии» и нажмите «Новый импорт».
2. В активной сессии вставьте текст выписки в поле «Выписка или уточнение» и нажмите «Отправить». Текущий интерфейс принимает текст через поле сообщения; отдельной загрузки файла нет.
3. Проверьте «Состояние выписки» и черновик в панели «Операции». Результат остаётся редактируемым.
4. Исправьте поля операции в редакторе или отправьте уточнение сообщением. Проверьте ошибки и отметки «Нужно проверить» перед экспортом.
5. Выберите нужные операции и нажмите «Экспортировать». Приложение скачает JSON batch; операция не отправляется в финансовый ledger.

Стабильная ссылка `/agent/sessions/{sessionId}` открывает выбранную сессию после reload. Диалог, черновик и выбранная конфигурация сессии сохраняются в локальной SQLite базе. Для отдельной выписки можно создать другую сессию. Новая выписка в текущей сессии дополняет черновик; точные дубликаты пропускаются.

## Настройки импорта

В активной сессии доступны provider, model и reasoning mode; изменения применяются к следующим сообщениям этой сессии. Панель «Настройки» содержит общие инструкции, которые применяются к следующим запросам во всех сессиях, категории и canonical merchant rules.

Панель «Фоновые задачи» настраивает периодическое чтение операций и чеков. Панель «MCP» показывает состояние интеграций. Она не нужна для обычного ручного импорта текста.

## Поддержка

1. Откройте вкладку «Поддержка».
2. Задайте вопрос об интерфейсе или использовании приложения.
3. Ассистент отвечает по FAQ и этому руководству; источники отображаются рядом с ответом. Если документы не подтверждают ответ, ассистент сообщит об этом вместо догадки.
4. После содержательного ответа ассистент спросит «Есть ли ещё вопросы?». Нажмите «Да» или задайте следующий вопрос, чтобы продолжить; нажмите «Нет», чтобы закрыть внутреннее обращение.
5. Вкладка сохраняет историю чата; внутренний ticket ID и status в интерфейсе не показываются. После 30 минут бездействия обращение закрывается. Новый вопрос после закрытия может продолжить старое обращение или начать новое; при неоднозначности ассистент задаст уточнение.

Support assistant использует отдельный provider/model/reasoning profile из `config/agent.json`. Настройки import sessions не изменяются настройками поддержки.
