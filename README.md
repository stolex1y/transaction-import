# Transaction Import

Transaction Import — web-сервис для извлечения финансовых операций из текстовых банковских выписок с помощью LLM.

Пользователь вставляет исходный текст, выбирает модель и параметры обработки, а затем получает структурированный результат с локальной проверкой перед импортом.

## Возможности

- извлечение операций из свободного текста;
- контролируемый JSON-ответ с единым контрактом данных;
- проверка обязательных полей, типов и предметных инвариантов до импорта;
- явная обработка неприменимых, неполных и невалидных ответов;
- отображение ответа модели, причины отказа, токенов и времени обработки;
- настройка модели, reasoning, формата ответа и token budget;
- сохранение результата обработки в JSON evidence из web-интерфейса.

## Web-интерфейс

Основная страница доступна по адресу `http://127.0.0.1:8080` после запуска сервиса.

В интерфейсе можно:

1. вставить банковскую выписку или свободную задачу;
2. выбрать провайдера, модель и параметры запроса;
3. отправить запрос в свободном или контролируемом режиме;
4. просмотреть исходный ответ и результат локальной валидации;
5. скачать результат обработки в формате JSON.

## Серия экспериментов

Раздел `/experiments` содержит страницы с заранее настроенными сценариями для последовательного сравнения режимов обработки:

- `/experiments/d01` — baseline unrestricted без выбора формата ответа;
- `/experiments/d02` — сравнение свободного ответа и controlled JSON;
- `/experiments/d03` — сравнение prompt strategies на свободной задаче;
- `/experiments/d04` — серия с preset temperature `0`, `0.7` и `1.2`;
- `/experiments/d05` — сравнение моделей DeepSeek и OpenRouter.

Каждая страница последовательно выполняет свой сценарий, показывает ход обработки и ошибки провайдера, а завершённый результат можно скачать как JSON evidence.

Для страницы D05 требуется `OPENROUTER_API_KEY`. Модель OpenRouter задаётся через `OPENROUTER_MODEL`; если переменная не задана, используется `z-ai/glm-5.2:free`.

## Формат результата

Контролируемый ответ содержит:

- `status` — результат обработки;
- `rejection_reason` — причина отказа, если вход или ответ нельзя импортировать;
- `transactions` — извлечённые операции;
- `unparsed_fragments` — фрагменты, которые не удалось надёжно разобрать.

Результат считается пригодным для импорта только после прохождения локальной проверки. Неприменимый вход возвращается явно и не смешивается с операциями.

## Запуск

Задайте ключи провайдеров в окружении процесса. Для базовых страниц нужен `DEEPSEEK_API_KEY`; для D05 дополнительно нужен `OPENROUTER_API_KEY`.

Соберите и запустите web-сервис:

```bash
./gradlew :web:installDist
./web/build/install/transaction-import-web/bin/transaction-import-web
```

После запуска откройте `http://127.0.0.1:8080`.

## Провайдеры

Сервис работает с провайдерами, совместимыми с используемым API-контрактом. Основной сценарий использует DeepSeek; страница D05 дополнительно поддерживает OpenRouter и выбор конкретной модели.
